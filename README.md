# 호르몬로그 (HormoneLog)

*한국어 · [English](README.en.md)*

> HRT(호르몬 대체요법) 기록 안드로이드 앱 · 로컬 전용 · 서버 없음 · 계정 불필요
> An offline Android app for logging hormone replacement therapy.

## 소개

HRT를 하면 투약은 매일·매주 하는데, 혈액검사는 몇 달에 한 번뿐입니다. 그래서 **검사와 검사 사이에는
내 호르몬 수치가 어디쯤인지 알 방법이 없습니다.** 주사 직후인지, 다음 주사 직전 바닥인지조차 감으로만
짐작하게 됩니다.

호르몬로그는 그 빈칸을 채웁니다. 투약 기록을 넣으면 공개 문헌의 약동학(PK) 모델로 **예상 곡선**을
그리고, 실제 검사값을 넣으면 그 값에 맞춰 곡선을 **내 몸에 맞게 보정**합니다. 검사값이 쌓일수록
곡선이 개인화됩니다.

- **기록은 전부 기기 안에만** — 서버 업로드도, 계정도, 네트워크 호출도 없습니다
- **근거 있는 것만 그림** — 파라미터 출처가 확보된 투여 경로만 곡선을 그리고, 나머지(젤)는 곡선에서 빼고 이유를 알려 줍니다
- **예상값과 실측값을 섞지 않음** — 예상은 청록 띠, 실측은 노란 마름모로 항상 구분해 표시합니다

**⚠️ 참고용 도구입니다.** 예상 곡선은 공개 문헌에서 유도한 *인구집단 근사치*이며 임상 검증값이 아닙니다.
앱은 진단·처방·용량 변경을 제안하지 않으며, 모든 데이터는 기기 안에만 저장됩니다(네트워크 호출 없음).

## 기능

- **처음 시작** — 6단계(쓰는 약과 반복 일정, 지난 투약 한 번에 기록, 고환 유무, 검사 단위, HRT 시작 전 검사값). 첫 단계만 빼고 모두 건너뛸 수 있습니다
- **투약 기록** — 약물·경로(주사 IM/SC, 경구, 설하, 패치, 젤)·용량·시각·주사 부위·상태(투약함/늦게/놓침). 패치는 µg/일 규격과 교체 주기로 기록합니다
- **반복 일정** — 요일·시각·종료일, 같은 약물 일정이 겹치면 확인 후 기존 일정을 종료하고 교체. 일정에 맞는 지난 투약은 몇 건인지 보여 준 뒤에만 기록합니다
- **검사 결과** — E2 / Total T 실측, 단위 변환(pg/mL·pmol/L, ng/dL·ng/mL·nmol/L), 검사 방식, 채혈 시각(모름 허용). 값이 예상과 크게 다르면 단위 착오를 먼저 알려 줍니다. 저장하면 예상과의 차이·주기 위치·보정에 쓰였는지(안 쓰였다면 이유)를 보여 줍니다
- **예상 흐름** — 문헌 PK/PD 파라미터 기반 E2·Total T 예상 곡선
  - E2: 에스테르별 3구획 모델(estrannaise.js), 경구·설하 1구획 모델, 패치
  - Total T: E2 지연 효과구획 + Hill 억제 + 사이프로테론 포화 억제. 고환 유무를 알려 주면 더 맞추고, "말하고 싶지 않음"이면 그리지 않습니다
  - **실측 검사값으로 경로별 보정** — 주사·경구/설하·패치를 따로 보정하고, 보정 폭은 −50%~+100%로 제한하며, 검사가 쌓일수록 범위가 좁아집니다
  - **모델 상태** 화면(보정에 쓴/안 쓴 검사와 이유)과 **근거 탐색기**(파라미터·출처·한계)
- **타임라인** — 날짜별 그룹, 월 단위로 접히는 매일 복용, 유형·약물·기간 필터와 검색, 행마다 수정·복제·삭제
- **알림** — 주사일(전날 저녁 + 당일), 매일 복용(30분 뒤 한 번 더), 검사 주기, 진료 예약. 알림의 **투약 완료**로 앱을 열지 않고 기록하고, 잠금 화면에는 중립 문구만 보입니다
- **다른 기록** — 컨디션·증상, 체중·혈압, 재고(투약하면 자동으로 줄고 소진 시점 예상), 추가 검사(LH·FSH 등)
- **병원 메모** — 진료 메모, 다음 진료 예약, 병원 정보(직접 입력, 번들 데이터·네트워크 없음)
- **리포트** — 병원 방문용 A4 PDF 또는 세로 이미지. 이름·앱 이름은 들어가지 않고, 공유할 앱은 직접 고릅니다
- **홈 화면 위젯** — 다음 투약과 투약 완료 버튼. 수치는 보여 주지 않습니다
- **백업·복원** — `.hlb` 파일에 모든 기록을 담고(암호 없이 저장됩니다), 복원 전에 내용을 미리 보여 주며 현재 상태를 따로 보관합니다. CSV 내보내기·불러오기는 건너뛴 행과 그 이유를 알려 줍니다 ([샘플](docs/sample/hrt_2month_sample.csv))
- **프라이버시** — 기록은 기기 안의 파일에만 저장되고 클라우드 백업과 기기 간 이전은 꺼져 있습니다. 최근 앱 화면 가리기·런처 이름/아이콘 위장("메모")·알림 문구 중립화를 켤 수 있습니다(휴대폰 설정의 앱 목록과 알림 머리글에는 앱 이름이 그대로 보입니다). 앱 잠금과 기록 암호화는 없습니다
- **화면 설정** — 다크·라이트·시스템, 글자 크기(기본·크게·아주 크게), 12/24시간
- 영어는 아직 지원하지 않습니다(문자열 분리 작업 후 예정)

## 아키텍처

멀티모듈 Gradle:

| 모듈 | 역할 |
| --- | --- |
| `app` | Jetpack Compose UI, 단일 `AppState` + 순수 리듀서(`RecordsReducer`, `ScheduleOps`, `MemoOps` …) + `AppViewModel`, 알림·위젯·파일 처리 |
| `core:domain` | 도메인 타입(`DoseEvent`, `LabResult`, `Regimen`, `VisitMemo` …), 단위 정규화 |
| `core:evidence` | 근거 번들 — 파라미터별 출처(provenance)가 갖춰져야만 경로 모델 활성화 |
| `core:model-engine` | E2 곡선 엔진, TT 억제 엔진, 실측 보정 엔진, 주기 분석 |
| `core:data` | 로컬 JSON 파일 영속화(`org.json`), 백업 파일, CSV 입출력 |

- 상태 전이는 전부 순수 함수이고(시계도 인자로 받음), 저장이 필요한 전이만 `ViewModel`이 파일에 반영합니다. 저장은 메인 스레드 밖에서 한 번에 하나씩 하고, 실패하면 화면에 알립니다
- 곡선은 근거 번들에 파라미터 출처가 있을 때만 그립니다 — 젤은 근거가 얇아 곡선에서 빼고 기록만 남깁니다
- 읽지 못하는 기록(더 새 버전이 쓴 것, 또는 날짜·수치가 말이 안 되는 것)은 불러오지 않고 지우지도 않은 채 그대로 보관했다가 다시 써 넣습니다. "모든 기록 삭제"는 이것까지 지웁니다
- 모델 파라미터·출처·검토 기록: [docs/evidence/README.md](docs/evidence/README.md)

## 빌드 & 실행

```bash
./gradlew :app:assembleDebug
./gradlew :app:installDebug         # 연결된 기기에 설치
./gradlew testDebugUnitTest         # 전 모듈 단위 테스트
```

화면 테스트(`app/src/androidTest`)는 앱의 기록과 설정을 지우고 시작하므로 **전용 에뮬레이터에서만** 돌립니다.
기기가 여러 대 연결돼 있으면 `ANDROID_SERIAL`로 에뮬레이터를 지정하세요.

```bash
ANDROID_SERIAL=emulator-5554 ./gradlew :app:connectedDebugAndroidTest
```

로컬에 Android SDK가 필요합니다(`local.properties`의 `sdk.dir`).

### 릴리즈 빌드

```bash
./gradlew :app:assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

키스토어가 없으면 debug 키로 서명해 사이드로드 가능한 APK를 만듭니다. 본인 키로 서명하는
방법은 [docs/RELEASE.md](docs/RELEASE.md) 참고. 배포판은
[Releases](../../releases)에 있습니다.

- Kotlin 2.3.21 · Jetpack Compose (BOM 2026.06.00) · AGP 9.1.1 · Gradle 9.3.1 · JDK 17
